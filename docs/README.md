# Project 文档索引

本目录沉淀 Project 仓库内与开发、部署、存储、Agent 接入和历史架构相关的文档。Project 在 YeYing 社区生态中的定位，以社区产品边界文档为总纲：

- [社区产品架构](https://github.com/yeying-community/books/blob/main/yeying/社区产品架构.md)

该文档明确 Project 是项目、任务、文件协作和团队工作流的业务系统，拥有任务状态、项目权限和业务上下文；Project 消费 Agent 提供的智能体运行能力，不直接承担智能体安装、模型编排或社区发布目录职责。后续优化 Project 时，应优先检查改动是否仍符合这个边界。

## 架构与接入

- [应用运行时协议与职责边界](./应用运行时协议与职责边界.md)：详细说明 Node Registry、Agent Runtime、Project 在应用中心、插件、智能体、OnlyOffice/Drawio 等能力上的职责划分，并给出自有应用运行时协议的演进方案。
- [智能体运行时协议设计](./智能体运行时协议设计.md)：定义 `Project -> Agent Runtime -> Node Registry` 的职责边界、Project 到 Agent 的 internal API、鉴权和兼容策略。
- [应用市场兼容入口与智能体运行时](./应用市场兼容入口与智能体运行时.md)：说明 Project 保留 `api/appstore/*` 历史兼容入口，但实际安装、升级、回滚和卸载转发给 Agent Runtime。
- [应用中心 AI 与 MCP 历史设计](./应用中心AI与MCP历史设计.md)：早期 Node 作为 AppStore 运行入口的历史设计，仅作背景参考，当前架构以 Agent Runtime 文档为准。

## 维护约定

- [文档目录规划](./文档目录规划.md)：定义后续 `docs/` 的目标目录结构、文档类型、命名规则、归档规则和维护流程；现阶段不要求立刻迁移历史文档。
- 新增文档优先使用中文文件名，避免出现只靠英文缩写判断含义的文档。
- 涉及社区生态边界时，先引用上方社区产品边界文档，再在 Project 仓库内补充 Project 自身实现细节。
- 历史文档必须在开头标明“历史文档”或“背景参考”，避免和当前架构文档混用。
- 生成式文档需要同步更新生成脚本的输出路径，避免重新生成英文文件名。
