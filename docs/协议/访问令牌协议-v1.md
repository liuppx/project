# Project 访问令牌协议 v1

## 1. 背景

Project 后续会被 Codex、Claude CLI、本地脚本和自动化工具调用，用于读取任务、同步讨论、更新任务状态和沉淀执行结果。当前这些工具没有稳定的机器访问凭证，只能依赖网页登录态或人工复制上下文，不适合持续协作。

本设计先只解决 Project 自身的访问令牌，不引入 Node、Agent、Wallet 或社区跨应用协议。后续如果要升级为社区统一身份方案，可以在本设计基础上扩展签发来源和授权确认方式。

## 2. 目标

- 用户可以在 Project 中创建、查看、禁用和删除访问令牌。
- 令牌可以被本地自动化工具用于访问 Project 的任务、项目、文件和讨论 API。
- 令牌必须有明确的用户归属、项目范围和有效期。
- 服务端只保存密钥哈希，明文密钥只在创建时展示一次。
- 所有自动化写操作必须可审计，能够追踪到令牌、用户、IP、客户端和目标资源。

## 3. 非目标

- V1 不做跨应用通用 token。
- V1 不要求钱包签名后才能创建令牌。
- V1 不让 CLI 持有钱包私钥、助记词或网页登录态。
- V1 不替代 Project 现有用户、项目、角色和权限体系。
- V1 不开放管理员级运维接口、部署接口或系统配置接口。

## 4. 使用场景

### 4.1 Codex Skill 拉取任务

开发者在 Project 中创建一个令牌，授权某个项目的任务读取和评论权限。本地 Codex Skill 使用该令牌读取任务详情、相关讨论和附件上下文，执行后把进度或结果写回任务评论。

### 4.2 多仓库协作状态同步

一个功能涉及 Project、Node、Agent 多个仓库时，每个仓库的自动化工具可以围绕同一个 Project 任务同步进度。Project 作为任务和讨论的事实源，令牌只允许读取任务和追加讨论，不允许越权修改项目设置。

### 4.3 本地脚本批量整理任务

维护者可以给本地脚本创建短期令牌，用于批量查询任务、补充标签、更新状态或生成周报。脚本完成后立即禁用或删除令牌。

## 5. 令牌模型

V1 推荐使用 `AK/SK + HMAC`，适合命令行和本地自动化工具长期使用。

```text
Access Key: yyak_xxxxxxxxxxxxxxxx
Secret Key: yysk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

服务端保存：

| 字段 | 说明 |
| --- | --- |
| `id` | 令牌 ID |
| `userid` | 创建令牌的 Project 用户 |
| `access_key` | 明文 AK，可索引 |
| `secret_hash` | SK 哈希，禁止保存明文 |
| `name` | 用户自定义名称，例如 `codex-local` |
| `scopes` | 可选能力范围，目前支持 `file_cabinet`；项目任务 API 为隐式基础能力 |
| `project_ids` | 可访问项目范围，空值不代表全局权限 |
| `expires_at` | 过期时间 |
| `last_used_at` | 最近使用时间 |
| `last_used_ip` | 最近使用 IP |
| `status` | `active`、`disabled`、`expired` |
| `created_at` | 创建时间 |
| `revoked_at` | 禁用或删除时间 |

明文 `Secret Key` 只在创建成功时返回一次。用户离开页面后无法再次查看，只能重新生成。

## 6. 授权边界

访问令牌是所属用户在所选项目内的另一种认证方式，而不是另一套业务权限体系。创建令牌时必须选择至少一个项目；请求同时受到以下边界约束：

- 项目、任务、讨论和任务附件资源必须能追溯到令牌授权的项目。
- 文件柜 API 只有在令牌包含 `file_cabinet` scope 时开放，并继续复用当前用户的文件柜所有者、创建者和共享权限。
- 标准控制器继续执行所属用户既有的项目角色、任务可见性和操作权限校验。
- 用户、组织、系统、License、应用市场和令牌管理等非项目级高风险 API 拒绝 AK/SK。
- 令牌不提供 `admin:*`、`user:*`、`system:*` 等全局授权能力。

## 7. 请求签名

客户端请求头：

```http
X-YY-AK: yyak_xxxxxxxxxxxxxxxx
X-YY-Timestamp: 2026-08-06T10:00:00+08:00
X-YY-Nonce: random-string
X-YY-Signature: hmac-sha256-signature
```

签名原文：

```text
METHOD
PATH
QUERY_STRING
BODY_SHA256
TIMESTAMP
NONCE
```

规则：

- `METHOD` 使用大写，例如 `GET`、`POST`。
- `PATH` 只包含路径，不包含域名。
- `QUERY_STRING` 按参数名排序后编码；没有参数时为空字符串。
- `BODY_SHA256` 对原始请求体计算 SHA-256；空 body 使用空字符串的 SHA-256。
- HMAC key 使用 `SHA-256(Secret Key)` 的十六进制小写字符串。客户端收到一次性 SK 后在本地派生；服务端直接使用保存的 `secret_hash`，无需保存或还原明文 SK。
- `TIMESTAMP` 与服务器时间偏差默认不超过 5 分钟。
- `NONCE` 在时间窗口内不可重复使用。

服务端校验顺序：

1. 根据 `X-YY-AK` 找到 active 令牌。
2. 校验令牌是否过期或禁用。
3. 校验时间窗口和 nonce 防重放。
4. 使用 `secret_hash` 对应的密钥校验签名。
5. 校验用户状态、项目成员关系、项目范围、文件柜 scope 和资源归属，并交由标准控制器校验既有业务权限。
6. 写入访问审计和最近使用信息。

## 8. API 设计

### 8.1 令牌管理 API

令牌管理接口使用普通 Project 登录态，不使用自动化令牌调用。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/token/lists` | 获取当前用户令牌列表，不返回 secret |
| `POST` | `/api/token/create` | 创建令牌，返回一次性 secret |
| `POST` | `/api/token/disable` | 禁用令牌 |
| `POST` | `/api/token/delete` | 删除令牌 |
| `POST` | `/api/token/rotate` | 重新生成 secret，旧 secret 立即失效 |

### 8.2 标准业务 API 的访问令牌认证

Project 不为 Codex、CLI 或其他自动化客户端维护单独业务 API。标准 API 同时支持网页登录态和 AK/SK 签名；验签后令牌作为所属用户的另一种认证方式，复用同一控制器、业务权限、工作流和审计。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/project/lists` | 查询令牌授权范围内的项目 |
| `GET` | `/api/project/task/lists` | 查询任务列表 |
| `GET` | `/api/project/task/one` | 查询任务详情 |
| `POST` | `/api/project/task/update` | 更新任务字段、状态或完成状态 |
| `POST` | `/api/dialog/msg/sendtext` | 追加任务评论 |
| `GET` | `/api/project/task/filedown` | 下载任务附件 |

文件柜 API 仍走标准 `/api/file/*` 控制器，但必须在创建令牌时勾选“文件柜”。未勾选时调用 `file-lists`、`file-search`、`file-add`、`file-save`、`file-upload`、`file-link`、`file-remove`、`file-move` 等接口会返回“访问令牌无权调用此接口”。勾选后也只代表允许进入文件柜 API，具体读写仍由 `File::permissionFind` 和共享权限决定。分片上传 `/api/upload/*` 仅允许 `scene=file_cabinet` 的上传会话，不开放 `image`、`generic_file` 或 `dialog_file` 场景。

使用 AK/SK 的标准 API 仍使用 Project 的统一返回格式：

```json
{
  "ret": 1,
  "msg": "success",
  "data": {}
}
```

令牌仅能调用可追溯到已授权项目的标准 API。用户、组织、系统、License、应用市场和令牌管理等非项目级高风险 API 不接受 AK/SK。

## 9. 前端入口

建议在个人设置中增加“访问令牌”页面：

- 展示令牌名称、项目范围、过期时间、最近使用时间、状态。
- 创建时选择名称、项目、文件柜权限范围和有效期。
- 创建成功后只展示一次 `Access Key` 和 `Secret Key`。
- 明确提示令牌会沿用当前用户在所选项目和文件柜中的既有权限。
- 支持禁用、删除、轮换密钥。

管理员后续可以增加全局审计页，但 V1 不是必需。

## 10. 审计

至少记录以下事件：

- 令牌创建、禁用、删除、轮换。
- 使用 AK/SK 的标准 API 写操作。
- 签名失败、令牌过期、项目越权和标准接口拒绝。

审计字段建议：

| 字段 | 说明 |
| --- | --- |
| `token_id` | 令牌 ID |
| `userid` | 令牌所属用户 |
| `action` | 操作类型 |
| `resource_type` | `project`、`task`、`file` 等 |
| `resource_id` | 资源 ID |
| `ip` | 请求 IP |
| `user_agent` | 客户端信息 |
| `request_id` | 请求追踪 ID |
| `result` | `success` 或失败原因 |
| `created_at` | 发生时间 |

## 11. 安全约束

- 令牌必须有过期时间，默认不超过 90 天。
- Secret 只展示一次，数据库只保存哈希。
- 每个令牌必须绑定具体项目范围。
- 禁用用户、移出项目、项目归档后，相关令牌访问必须失效或受限。
- AK/SK 请求不依赖网页登录态；若同时携带登录态，仍以令牌所属用户和令牌项目范围为准。
- 所有失败响应不要泄露 AK 是否存在、资源是否存在等敏感判断细节。
- 可对单个 AK 增加速率限制，避免脚本失控。

## 12. 实施阶段

### 阶段一：最小可用

- 增加令牌表和访问审计表。
- 实现 AK/SK 生成、哈希保存、禁用、删除和过期校验。
- 实现 HMAC 鉴权中间件或鉴权服务。
- 让标准项目、任务、讨论和文件 API 接受 AK/SK 认证。
- 增加个人设置中的令牌管理页面。

### 阶段二：协作闭环（已实现）

- 增加任务状态更新和普通字段更新。
- 增加文件只读下载能力。
- 增加令牌轮换和最近使用信息。
- 增加 Codex Skill 接入示例文档。

### 阶段三：协议增强（已实现）

- 增加 nonce 存储和更严格的重放保护。
- 增加令牌级速率限制。
- 增加管理员审计视图。
- 预留钱包签名确认创建令牌的扩展点，但不在 V1 强制实现。

### 阶段二、三实现说明

- 任务字段和状态更新复用标准接口的完整参数契约、工作流、权限、日志和推送逻辑。
- nonce 使用 `automation_token_nonces` 表的 `(token_id, nonce_hash)` 唯一约束原子防重放，过期数据由请求低频清理。
- 令牌限流默认为每分钟 60 次，可通过 `AUTOMATION_TOKEN_RATE_PER_MINUTE` 调整；签名时间窗口通过 `AUTOMATION_TOKEN_TIME_WINDOW` 调整。
- 管理员可在「访问令牌审计」页按操作、结果和用户查询访问记录。
- `AutomationTokenCreationAuthorizer` 是创建与轮换前的外部授权扩展点；默认未配置，V1 不强制钱包签名。
- Codex Skill 提供 `projects`、`tasks`、`task`、`comment`、`update`、`status`、`file-info` 和 `download` 命令。

## 13. 后续扩展预留

如果未来要接入社区统一身份，可以把“创建令牌”前的用户确认步骤升级为钱包签名 challenge。但 Project 仍然负责最终签发 Project 域内令牌，并继续校验项目权限和资源归属。

扩展原则：

- 钱包证明身份和授权意愿。
- Project 决定 Project 资源权限。
- 自动化工具只持有 Project 签发的受限令牌。
- 不设计跨所有应用默认可用的全局万能 token。
